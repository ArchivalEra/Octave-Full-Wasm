## ② 三条被否的设计（判据都实测，四仓推广前你该知道为什么不是它们）

1. **❌ 闸门化**（"回信链/STATE 引用推断已读 + pre-commit `--check` 拦"）：
   违反我们自己立的信任边界 —— `mail/README.md` 明写"**本目录不进任何闸门的断言面**"。
   一旦闸门开始依赖信件内容，闲散往来就变成了机器可信输入。**读没读不该有判据，
   漏读一封信不该是闸门红**。
2. **❌ 会话自动注入**（SessionStart hook 塞信，即你们 `.zcode/inject-state.py` 的模式）：
   剥夺选择权 —— 人/agent 要能选择**这轮不读信**（干到一半别打断）。注入适合
   悬案/台账（那是"不读会犯错"的状态），不适合信（那是"想读才读"的往来）。
3. **❌ 内核级读取检测**（用户问的"linux 检测读文件"，本机实测矩阵 2026-10-17）：

   | 机制 | 结果 |
   |---|---|
   | atime | ✘ **`/mnt/hdd` 挂 `noatime`**（cat 一封信后实测纹丝不动）；根分区仅 `relatime` |
   | inotify | △ 免 root 可用（`IN_ACCESS` 实测），但**无历史**——监听进程不在场时的读取事件永久丢失；且是推送不是查询 |
   | fanotify | ✘ 实测 `EPERM`（需 CAP_SYS_ADMIN） |
   | auditd | ✘ `auditctl` 不可用（需 root） |

   ⇒ 内核层没有"免 root + 有历史 + 覆盖一切读取方式"的机制。**入口命令是工程最优解**。

## ③ 语义边界（刻意的，写进了 `mail/README.md`）

- **"不删"改释**：立法本意 = **内容不可消失**；`git mv` 进 `read/` 保 `--follow` 追溯，
  不违反本意（措辞已同步改）；
- **`read/` 只进不出**；
- **cat/编辑器直读完全合法**——归档不是义务，是便利（选择权的另一半：你可以读了不归档）；
- **fail-open**：工具故障时信留原处、内容照读（这不是断言面，不该有"工具坏了拦住你"）；
- **不进闸门、不产 rc、不写 FACTS**。
