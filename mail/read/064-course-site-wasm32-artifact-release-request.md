## ① 我们是谁、要什么（只说必要的）

一个纯静态的课程阅读站（Node 自建构建器、无框架、零第三方运行时依赖、CDN 托管）。站内约一万两千条数学公式现在是构建期烘死的静态 HTML，读者只能看。

我们要：读者点公式 → 编辑 → 点运行 → 用 Octave 算 → 结果贴回来。

硬约束：

- **只要 wasm32**，不要 wasm64，不要 omc / Modelica；
- 纯静态托管，**没有自己的后端进程**；
- **必须 vendor 进我们自己的仓**（不引外部域名请求，这是本站规矩）；
- 必须能在**没有 COOP/COEP 响应头**的环境下跑（我们只能控制静态文件，控制不了响应头）。

## ④ 具体问题（逐条可答）

**Q1｜有没有计划发 Release？** 如果有，大概什么时候、asset 命名是什么？如果没有计划，请直说——我们另想办法而不是等。

**Q2｜如果暂时没有 Release，我们该走哪条？** 有三个候选，请指一条：

- (a) 你们在某个分支/某个路径里其实存了产物（我们没找到，请给路径）；
- (b) 我们照 `build/Makefile` + `link-web.sh` 自己编（请确认：给定 emcc 5.0.7，这条路在普通 x86-64 Linux 上是否可行、大概要多久、有没有我们必须知道的坑）；
- (c) 你直接给我们一份产物（放到任意我们能取的地方，或告诉我们 Octave-UI 那份是不是可以当基准）。

**Q3｜产物完整性怎么验。** 你们有没有官方 sha256 清单（每个文件的）？我们要在 vendor 时锁死并写进仓库。如果只有 `octave.build.json` 里的元数据，够不够当凭据？

**Q4｜许可证与再分发。** 我们要把产物**连同 `octave.js` / `octave-core.js` 这些胶水一起 vendor 进公开仓库**（AGPL-3.0 的仓）。请确认：这样做符合你们的许可安排吗？需要我们在仓里附带哪些文件（`THIRD-PARTY-NOTICES.md`？`LICENSE`？）？

**Q5｜最小调用面。** 我们只需要「给一段 Octave 代码，拿回 stdout」。请确认最小必需的入口是 `octave.js` 还是 `octave-core.js`，以及是否必须同时带 `octave-worker.js`（Octave-UI 说他们单线程直接调、不用 Worker——我们也想这样）。

**Q6｜有没有更小的产物。** 完整 Octave 37.96 MiB 里，我们大概只用得到基础数值计算（矩阵、sin/cos、求导积分、符号运算少量）。你们有没有「精简档 / 无工具箱档」的构建？如果有，体积多少？没有的话，请直说——我们按完整档规划。
