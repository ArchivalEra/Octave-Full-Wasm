## §0 目标：这次不是"能不能"，是"最终版长什么样"

**wasm64 是最终版本。** 它的形状是：

```
主路径   = memory64 + 多线程        （真 64 位地址空间 + 并行；需要引擎支持 memory64 且宿主发 COI）
兼容回退 = memory64 + 单线程        （同一个 64 位产物，不并行）
底线     = 现有 wasm32 双档不许退化  （任何静态托管上都必须能跑 —— 这是 B6 立下的红线）
```

⇒ **验收不是"memory64 能跑"，而是"memory64 在【线程】与【单线程】两种配置下都能跑，
且选档机器在两条轴上都不出错"**（§2）。

**但仍要先过可行性门。** 按顺序三问，**别跳**：

**Q1 浏览器能跑吗 → Q2 `.oct` 还活吗（两种配置各跑一遍）→ Q3 内存上限能到多少。**
任何一问不过 ⇒ **停下写否证**，后面不用做。

- **产物**：`build/113/NOTES-wasm64.md`（实测/推断分开，每句旁边写复跑命令）。
- **分支**：新开一个（建议 `wasm64`），从 `open-questions` 切。
- **禁区**：不许动 `8761`/`8768`，不许 promote。一次只动一个轴。

## §2 两条轴 —— 先想清楚要发几份产物

选档现在只判**一条轴**（`bridge/lane.js`：COI 有/无）。memory64 加上**第二条轴**（引擎支持/不支持），
最多四格：**① memory64+线程**（目标形态）· **② memory64+单线程** · ③ wasm32+线程（今天）·
④ wasm32+单线程（今天）。⇒ 要定：**发几份**（四份≈4×30MB wasm，砍到几份的代价是什么？）、
**回退顺序**（memory64 ✗ 的引擎走现有 wasm32 双档 —— 那就是"单线程兼容回退"的落点）。

选档机器本身也在验收里：两轴**同步判据** + **选错就响亮失败** + `?lane=` 覆盖仍可用。

（`MEMORY64=2` 要不要：它是"按 64 位编、Binaryen 降回 wasm32"，**我怀疑**拿不到 >4 GiB ⇒ 只是工具链
兼容模式。**待你证伪，不是结论** —— Q3 里测它。三个决策点的展开见附录。）

## §3 三问与判据

### Q1 · 浏览器里能跑吗？

- **做什么**：照 `test/browser/probe-lane.mjs` 的骨架写一个最小页，加载 `-sMEMORY64=1` 的平凡模块，
  记录：能否实例化、`crossOriginIsolated`、**`SharedArrayBuffer` 还在不在**、引擎版本与报错原文。
- **怎么跑**：`cd /mnt/hdd/octave-wasm-build/harness && sh run.sh <你写的.mjs> <URL>`
  （**别 `node` 直跑**：`import 'playwright-core'` 按脚本所在目录解析）。
  自起站点：`python3 build/serve-coi.py --dir <目录> --port <端口>`；探针要在**顶层页**上做。
- **判据**：`rc=0` ⇒ 能实例化 **且** 现有选档仍生效 ⇒ 进 Q2；`rc=7` ⇒ 引擎不支持 ⇒ **写否证并停**。

### Q2 · `.oct` 还活得了吗？（**命门**，**两种配置各跑一遍**）

- **为什么**：`.oct` 是 side module，`dlopen` 装载、符号靠**主模块导出面**解析，线程档还要求每个
  `.oct` 带 `_emscripten_tls_init`。§1 只证明了"最小 side module 能装"，
  **没有**证明 `memory64 × dylink × 主模块 pthread` 三者叠加成立。
- **做什么**：在 memory64 产物上重跑已有判据，一个都别省 ——
  **① 线程配置**（`-pthread`，对应 §2 的格子①）与 **② 单线程配置**（对应格子②）**各一遍**：
  ```bash
  python3 build/113/check-oct-lane.py <站点>/assets/oct-threads <站点>/assets/octdir-threads \
          --base <站点>/assets/oct <站点>/assets/octdir
  python3 build/113/check-oct-imports.py
  # 再加三套：accept-113-oct / accept-dldfcn / accept-full
  ```
- **判据**：**两种配置都**三套全绿 **且** `check-oct-lane.py` 无报 ⇒ `rc=0` ⇒ 过；
  任一红 ⇒ 记录**是哪一条规则** + 最小复现，说清"memory64 引入的"还是"既有的"，
  并明确是**哪一格**红的（① 还是 ②）—— 回退设计靠这个信息。

### Q3 · 收益到底有多少？（**这条决定值不值**）

- **做什么**：浏览器里实测**可寻址上限**（**不是** "声明了多少"）。`MAXIMUM_MEMORY` 设到 5 GiB / 8 GiB
  分别测 ① 构建能否过 ② 运行时**实际能分配多少**；**两种配置各测**。
- ⚠️ **别预设两种配置上限一样**：`§1` 只验了"`-pthread -sSHARED_MEMORY` 能链接"，
  **没有**验过"共享内存 × memory64"跑起来怎样。共享内存那个上限有可能不同 —— 测出来再说。
- **判据**：给出一个**数字** + 复跑方式。
  `rc=0`（拿到 >4 GiB）⇒ 有收益，进 §5 的最终版验收；`rc=7`（拿不到）⇒ **零收益，写否证并停**。
- ⚠️ **这是 fail-closed 出口，请认真用它**，别为了"做完"硬推。

## §5 四个"别踩"

1. ★ **跑工具前先读它的用法**。本仓刚踩过：`relink.sh verify --out <副本>` 会**假红并把
   `verdict` 写成 `rejected`**（它按身份证里记录的构建目录找兄弟文件）。
   ⇒ **验副本必须在产物原位验**。
2. **容器里的构建脚本是另一份拷贝**。改完仓库的 `relink.sh`/`link-web.sh` 必须 `docker cp`

3. **禁止 `sleep`（任何形式）**；长任务用 `setsid nohup … &` 或后台任务，靠完成通知收尾。
   **跑验收时别并行干重活**（并发压缩曾让套件假崩）。
4. **探针/自检不许放在开机路径上**：坏产物会让整页卡死，连带所有浏览器验收全挂。

### §2 那三个决策点的展开（真要做决定时再看）

**先量，再定，别反过来。**

1. **发几份**：四格各一份 = 4×~30 MB wasm（首包会很痛）。可行的减法：memory64 的**两个配置**
   是否真需要两份产物？—— `-pthread` 是**链接期**旗标（共享内存的位在 wasm 头里），
   所以**是**两份。可考虑的替代：只发 memory64+线程 与 **wasm32 双档**（放弃 ② 格），
   代价 = 拿到 memory64 但拿不到 COI 的宿主会退回 wasm32（≤4 GiB）。**这个取舍要你量完再报。**
2. **回退顺序**：建议 **memory64+线程 ＞ memory64+单线程 ＞ wasm32+线程 ＞ wasm32 单线程**
   （先要地址空间，再要并行）。顺序要写进 `lane.js` 的判据里，并配"选错就响亮失败"的断言。
3. **`MEMORY64=2`**：只有 Q3 测出"**2 也能拿到 >4 GiB**"它才值得考虑（那它就能一份产物两用）；
   否则**不要** —— 多一个产物档位只换来更慢的执行。
