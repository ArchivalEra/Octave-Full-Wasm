# Octave-Full-Wasm — GNU Octave 11.3.0, WebAssembly build

> **Naming**: this release is identified as **`Octave-Full-Wasm/vX.Y.Z`** — our own version
> axis, in the same shape as `LLVM-wasm/v0.1.6`. The upstream project publishes under
> `release-11-3-0` / "Octave 11.3.0", so reusing that number here would put two different
> products in the same namespace. "GNU Octave 11.3.0" stays in the title as a *description*
> of what the binary contains, not as our identity.

One trunk produces three artifacts from three parameter sets. All three are built by the
**same** `build/113/link-web.sh` (the manifest's `tool.script_sha256` is identical across them,
so "three products from one build recipe" is machine-checkable rather than asserted).

| product | arch | what it is |
|---|---|---|
| `wasm32` | wasm32 | single-threaded, **zero atomics** — runs in pages that send no COOP/COEP |
| `wasm64std` | wasm64 | standard: wasm64 + mimalloc, does **not** link `librustsort.a` |
| `wasm64ip` | wasm64 | same plus the Rust sort kernel (`librustsort.a`) |

## Licence

All three products are **AGPL-3.0-or-later**, the licence of this repository. The Rust sort
kernel is this repository's own source (`build/113/rust/src/lib.rs`, `#![no_std]`, no third-party
crates); the seam lives in our own fork of Octave at `f4bf15b` and is declared
`__attribute__((weak))`.

A previous revision of this release labelled `wasm64ip` with
`LicenseRef-nonfree-rust-sort-kernel`. **That was wrong and is withdrawn.** It came from
reusing a *maintenance* word — "non-free because it leaves the open-source community", meaning
upstream does not accept the patch — as a *licence* term. See
[`docs/RUST-SORT-KERNEL-LICENSE.md`](../docs/RUST-SORT-KERNEL-LICENSE.md) for the full record.

## Format

Static-Contract release contract v4 + v1.1: `schema: 3`, one `manifest.json`, flat assets,
names from the platform whitelist, chunks ≤ 5 MiB, four codecs (`zstd`, `gzip`, `br`,
`identity` — `br` added per the ecosystem release protocol: brotli q11 sidecars for payloads
≥ 1 MiB, saving a further ~31% over gzip -9 on this release's bytes; small payloads ship
gzip/zstd/identity only, already-compressed formats get none),
plain GET only — no Range, no conditional requests, no custom headers.

The contract's catalogue lives at **`https://static.isui.ren/`** (moved there by site ruling
2026-11-03; the publication surface is deliberately narrow — shelf + contract only). Both
`v0.1.x` entries are listed there and verified online as `AGPL-3.0-or-later` with zero
`LicenseRef`. The validator used at publish time is cloned from the canonical repo
`ArchivalEra/Static-Contract` (`tools/check-release-v4.py`, fingerprint-checked).

The manifest is generated by `build/make-release.py` from the bytes committed under
`release/products/`, and this release is published by `.github/workflows/release.yml`. Nothing
in it was hand-edited: the workflow runs the generator's own self-test, then the contract's
`check-release-v4.py` against the generated output, and refuses to publish on any failure.

## Lane identity (engine contract)

The top-level `lanes` object is the **engine contract's** lane declaration, projected from
`build/lanes.json`'s `release_identity` (the single source). It splits two things that the
distribution contract deliberately keeps separate: **lane** = which product line you chose
(`wasm32-final` / `master` / `IllegalPerformance`), **product** = which byte group inside the
release to fetch (`wasm32` / `wasm64std` / `wasm64ip`). `products` itself is unchanged: those
ids are delivery coordinates, not identities. Each lane also records its `build_mode` (the
`relink.sh` mode name), `arch`, `threads`, and `coi_required`. No new vocabulary is introduced —
all three name sets come from existing sources. The generator proves the projection by reading
it back from the generated manifest and reconciling it against the three product directories
and each `octave.build.json`'s `build.mode`; any drift refuses to publish.

## The wasm32 product

That product exists for one reason: it must run where cross-origin isolation is impossible
(static hosting, no `COOP`/`COEP` headers). Two criteria hold it in place, both read from
*bytes* rather than from build flags:

- `b'atomics'` appears **0** times in `octave.wasm`;
- a page served with no COOP/COEP boots it and evaluates `2+2 = 4` with
  `crossOriginIsolated === false` and `typeof SharedArrayBuffer === "undefined"`.

## Choosing a product

`manifest.json`'s `products` map is the machine-readable form of the decision: pick by `arch`,
and be aware that only `wasm64ip` links the Rust kernel. Nothing here restricts redistribution —
the split is a build distinction with a behavioural difference, not a licensing barrier.
