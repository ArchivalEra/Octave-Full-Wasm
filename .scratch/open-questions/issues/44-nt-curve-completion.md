# 44: **NT>8 线程数曲线补测**（NT=12/16）——"NT=8 是极限"这句话的最后一格实测

**What to build:** 票 05/41 之后，线程–性能曲线只实测了 NT=4 与 NT=8 两点；"NT=16 不必试"
的决定是在**已被翻案的死锁理论**下做的（票 41 真因 = `-flto` 漂移）。用户拍板（2026-10-03）
补测 NT=12/16，把"NT=8 是不是性能极限"变成有实测背书的结论。

**实验设计（唯一变量 = OpenBLAS 编译期 NUM_THREADS）**：
- 池保持 `PTHREAD_POOL_SIZE=4` 不动（**现役 NT=8 产物实测就是 pool=4**，`pthreadPoolSize=4`
  —— 收益本来就是在"按需补建 worker"形态下拿到的）⇒ 吞吐对比只看 NUM_THREADS。
- 构建：`E2_LANE=w64 E2_NUM_THREADS=<n> WORKDIR=/src/work/OpenBLAS-e2-w64-nt<n>
  OUTLIB=/src/work/e2-openblas-lib-w64-nt<n> bash /src/bin/build-e2-lane.sh src patch build`
  （洁净源副本 + 补丁，与 nt8 同配方）；重链：`E2_OPENBLAS=…-nt<n> relink.sh link w64`
  （洁净脚本，**不带 --diag**）。
- 站点：8812（nt12）/ 8816（nt16），克隆 nt8 站结构后只换 `w64/` 三件。
- **同日同窗参照**（NT=8，8761，今日全量轮）：matmul500 **0.004**、matmul1000 **0.025**、
  lu800 **0.015**、lu1500 **0.063**；dgemm512 **0.004** / dgemm1024 **0.028** / dgemm2000 **0.199**。
- **主判据**：吃线程的 matmul1000 / dgemm1024 / dgemm2000（原生 24 线程 vs 浏览器 NT 的差距
  在大矩阵最大——matmul1000 只占原生天花板 ~31%）。
- **可行性判据**：`accept-dldfcn` 必须全绿（dlopen 面，71/0）——线程更多 ≠ 可交付。

## Answer

（2026-10-03 补测结案。全部数字可复跑：`w64-logs/il-nt{12,8}-r{1,2,3}.log`（交错 3×3）、
`bench-nt12.log` / `bench-nt16.log` / `dgemm-nt{12,16}.log`、今日 NT=8 参照 =
`sweep-logs/20261003-074606/bench-*.log`。）

**结论：NT=12 与 NT=16 都不快于 NT=8，曲线峰在 8。**

- **交错 3×3**（12→8→12→8→12→8 同窗配对，摊平时变负载；matmul1000 / lu1500 / matmul500 中位数）：
  - NT=12：0.029 / 0.070 / 0.005
  - NT=8：**0.027 / 0.065 / 0.003**
  ⇒ NT=12 三格全都不快于 NT=8（-7% / -8% / -67%——matmul500 差距最大，小矩阵对线程开销最敏感）。
- **NT=16**（单轮，方向已一致）：matmul1000 0.025（=NT=8）、lu1500 **0.074**、svd **0.211**、
  sort **0.293** 全面更差；dgemm1024 0.028（平）、dgemm2000 0.194（-2.5%，**噪声级**，
  被其余全部用例反向）。**不采纳**。
- **dgemm 直测**：dgemm1024 / dgemm2000 —— NT=8 0.028 / 0.199；NT=12 0.035 / 0.215；NT=16 0.028 / 0.194。
- **可行性**：`accept-dldfcn` NT=12 **71/0**、NT=16 **71/0** —— 都是可交付产物，只是不更快。
- **★ 方法论教训（本单最大的收获之一）**：单轮 bench 在这台机器上**不可当判决** ——
  NT=12 首轮 matmul1000 测出 **0.019**（比 NT=8 快 24%），交错复跑立刻退回 0.028–0.033。
  本机（隔壁 GPU 负载 + 浏览器调度）的运行间方差 ≈ ±30%，**任何"快了百分之几"的单轮结论
  都必须交错复跑 ≥3 轮再说话**。这解释了为什么票 05 的初版曲线（NT=4 甜点）会被翻案两次。

**终局**：现役 NT=8（`f2269106…`）保持不动。"NT=8 形态是性能极限"现在有完整实测背书：
4 → 8 = **+2.0–2.2×**；8 → 12/16 = 持平偏降（曲线过峰）。NT=12/16 产物留档
（`w64-ob-nt{12,16}-clean-out`，实验站 8812/8816 可复跑）。
